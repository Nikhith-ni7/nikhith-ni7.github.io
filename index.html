Four labs that cover the full path: write the detection, test it, deploy it, triage the alert, investigate the incident.

01 · DETECTION AS CODE

Detection-as-code pipeline

Windows detections written as Sigma rules, linted and replayed against labelled events on every push, then converted automatically to Splunk SPL and Microsoft KQL for Defender XDR and Sentinel. The rules cover ClickFix, LOLBins, LSASS dumping, Defender tampering, Kerberoasting and shadow-copy deletion.

CI fails if a rule doesn't lint, a test event behaves unexpectedly, or a captured attack goes undetected. A custom Sigma evaluator fails loudly on unsupported features, so no rule can pass by being silently skipped.

03 · AI IN THE SOC

AI-assisted alert triage

A Python CLI and local dashboard that triages Wazuh and Sentinel alerts. Decision rules set the verdict. A local LLM (Qwen3 via Ollama) writes the triage note, orders the investigation steps and gives a second opinion. An analyst approves or replaces every verdict.

To block prompt injection, the model only sees a schema projection: no log text, IPs, hashes or paths. Its output is checked against allowed ATT&CK IDs and a fixed list of investigation steps.

04 · INCIDENT RESPONSE

Ransomware precursor investigation

Detects and links three steps that often come before ransomware: Kerberoasting across domain controllers, certificate abuse through a misconfigured AD CS template (ESC1), and deletion of shadow copies and backups.

Findings that share an account within two hours are grouped into an unconfirmed same-actor hypothesis, listed with the evidence still needed to confirm it, and written up as a full incident report. The project documents its known evasions and limits.

05 · APPROACH

How I build detections

Three habits that run through every project.

✓

Test every rule

Each detection ships with positive and tricky negative cases, and CI blocks anything that regresses. A rule without a test is a guess.

◐

Separate verified from pending

Every project marks which results are verified and which are still pending. Synthetic data is labelled as synthetic, and known limits and evasions are written down.

⌘

Keep the analyst in control

Automation drafts and advises, and a person decides. Containment is allow-listed and dry-run by default, and models can't record a verdict.
